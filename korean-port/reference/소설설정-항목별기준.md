# 소설 설정의 항목별 작성 기준

이 문서는 현재 설치한 InkOS 1.8.0과 고정된 2.0.0 소스에서 실제 사용하는 설정·집필 항목을 기준으로 한다. 원본 파일의 이름만 채우는 대신, **항목마다 목적·맥락·판단 기준·적용 경계가 드러나도록 작성**한다. 예시는 선택지를 설명하며 특정 작품의 확정 설정을 뜻하지 않는다.

## 모든 항목에 적용하는 작성 방식

각 항목의 실질 내용에는 다음 네 질문의 답이 있어야 한다. 서술형 문서에서는 답을 자연스러운 문장에 녹인다. 기계가 읽는 JSON·표에는 새 열이나 키를 임의로 추가하지 않고, 설명은 대응 Markdown이나 기존 `notes`에 둔다.

| 질문 | 작성할 내용 | 불충분한 표현 | 충분한 표현의 예 |
| --- | --- | --- | --- |
| 목적 | 이 설정이 어떤 독자 경험·인물 선택·사건 인과를 만드는가 | 주인공은 강하다 | 주인공의 실력은 동료를 구할 선택권을 주되, 조직 전체의 문제를 혼자 없애지는 못하게 한다. |
| 맥락 | 언제·어디서·누구에게·어떤 선행조건 아래 성립하는가 | 내공을 못 쓴다 | 단전 부상 회복 전에는 장시간 운기를 못 한다. 짧은 순간의 발경은 가능하지만 후유증이 남는다. |
| 판단 기준 | 어떤 관찰 가능한 장면·상태로 지켰는지 판단하는가 | 신뢰가 생긴다 | 상대가 손해를 감수하고도 맡은 호송을 지켜, 다음 의뢰에서 정보를 먼저 공유한다. |
| 적용 경계 | 무엇까지 허용하고 어디부터 적용하지 않는가 | 가벼운 무협 | 대화와 일상에는 유머를 허용하되, 사망·부상·배신의 결과를 농담으로 무효화하지 않는다. |

판정 가능한 문장으로 쓴다. 근거가 없으면 `미정`·`작가 선택 필요`·`초안 가정`으로 남기고 확정 정사처럼 말하지 않는다. 비적용 항목은 적용하지 않는 이유를 짧게 쓴다. 같은 사실의 원본을 여러 파일에 중복 보관하지 않고 원본 위치를 가리킨다. 새 요구가 과거 계획과 충돌하면 변경 범위와 영향을 밝히며, 이전 계획을 이미 일어난 사건으로 취급하지 않는다.

**정사**는 본문 또는 작가가 확정한 초기 조건이다. **계획**은 앞으로 일어날 후보이며, **가설**은 인물이 믿는 설명이다. 세 가지를 구별한다. 관찰·증언·추측도 구별한다. 항목의 경계에는 적용 기간, 예외 조건, 인물의 정보 범위, 변경 권한 중 필요한 것을 명시한다.

## 버전과 저장 위치

| 대상 | 1.8.0 | 2.0.0 | 작성 경계 |
| --- | --- | --- | --- |
| 기본 설정 | `books/<id>/story/` 아래 골격·권 지도·인물·규칙·상태 | `works/<id>/source/story/` 아래에 작품 프로필·전문 Skill·foundation 도구로 골격·권 지도·인물·규칙을 저장 | 실제 `StateManager.bookDir()`가 가리키는 위치를 따른다. 경로를 추측해 중복 작품을 만들지 않는다. |
| 골격·권 지도 | architect 프롬프트가 구체적 절·분량·권 단위 구성을 제시 | architect는 아티팩트·도구 계약을 관리하고 집필 방법은 활성 Skill이 공급 | 아래 항목은 의미상 공통 기준이다. 1.8의 절 제목을 2.0의 필수 JSON 키로 이식하지 않는다. |
| 규칙 | `book_rules.md`를 읽고 구조화 규칙을 추출, 레거시 YAML도 지원 | `book_rules.md`와 strict `book_rules.json`을 함께 저장 | 2.0 JSON에 1.8 전용 필드를 덧붙이지 않는다. |
| 복선 | `payoffTiming`, `coreHook`, `halfLifeChapters` 등 메타데이터 지원 | 축소된 strict HookRecord, `superseded` 상태 지원 | 버전별 스키마에 있는 필드만 전송한다. 나머지 설명은 기존 `notes`·사람이 읽는 문서에 둔다. |
| 장르 | `genres/*.md` 프로필 | 장르 디렉터리 대신 작품·Skill 구조 | 현대 라이트 무협 지침은 작품 선택에 적용한다. 모든 한국어 작품을 무협으로 해석하지 않는다. |

원본: [1.8 architect](/workspace/inkos/packages/core/src/agents/architect.ts), [2.0 architect](/workspace/inkos-latest/packages/core/src/agents/architect.ts), [2.0 foundation 설계](/workspace/inkos-latest/packages/core/skills/inkos-long-writing/references/foundation-design.md).

## 작가 의도와 현재 집필 방향

`story/author_intent.md`와 `story/current_focus.md`는 자유 서술형 통제 문서다. 한국어 기본틀의 네 요소를 각 실제 선택에 구체화한다. 아래 항목은 이를 돕는 **작성용 소제목**이며 신규 네이티브 JSON 필드가 아니다.

| 파일 / 항목 | 목적 | 맥락 | 판단 기준 | 적용 경계 |
| --- | --- | --- | --- | --- |
| `author_intent` / 작품의 약속 | 독자가 계속 읽을 핵심 경험을 정한다 | 장르·대상 독자·장편 규모 | 초반과 주요 권에서 같은 약속이 사건으로 확인된다 | 유행·플랫폼 관습을 작가의 명시적 요구보다 우선하지 않는다 |
| 중심 질문·주제 | 인물의 선택에 지속적인 압력을 준다 | 인물의 결핍과 적대 구조 | 서로 다른 선택의 대가가 장면에 드러난다 | 교훈 설명·정답 설교를 강제하지 않는다 |
| 장르 혼합·비중 | 어느 이야기 축을 얼마나 보이게 할지 정한다 | 성장·관계·사건·생활 등 | 권과 짧은 전개 주기에서 각 축의 사건·후과가 보인다 | 비율을 단순한 문장 수 할당으로 바꾸지 않는다 |
| 독자·수위·민감 요소 | 표현의 강도와 시선을 일관되게 한다 | 목표 독자와 작가가 지정한 범위 | 잔혹·성적·비극·개그 장면을 같은 기준으로 검토한다 | `라이트`만으로 전연령·무피해 세계를 확정하지 않는다 |
| 배경·시대·지역 | 공간과 제도의 인과를 고정한다 | 가상 강호·역사 기반·현대 변형 중 선택 | 이동·경제·관습·관직·문파 관계가 양립한다 | 한국어 집필이 한국 배경을 뜻하지 않는다. 실제 역사와 가상 설정을 구분한다 |
| 시점·서술 거리 | 독자에게 허용할 정보와 문체를 정한다 | 인물의 인지 범위·장면 구성 | 숨긴 정보와 시점 이동에 이유가 있다 | 미지정 시점을 작가 확정값처럼 잠그지 않는다 |
| 금지·허용·변경 절차 | 지켜야 할 약속과 실험 범위를 구분한다 | 작가의 최신 명시적 요구 | 위반·예외·변경 영향이 추적된다 | 모호한 취향을 자동 심사 탈락 규칙으로 승격하지 않는다 |
| `current_focus` / 현재 목표 | 다음 집필 범위를 좁힌다 | 다음 1–3회와 최신 정사 | 목표가 장면·선택·상태 변화로 확인된다 | 전체 작품의 주제·결말을 임의 변경하지 않는다 |
| 우선순위·완료 조건 | 동시 과제의 충돌을 해결한다 | 지금 독자가 기다리는 약속 | 무엇을 먼저 진행하고 언제 완료하는지 보인다 | 모든 복선을 매 회차 진전시키도록 강제하지 않는다 |
| 유지·보류·미정 | 현재 작업의 변경 범위를 지킨다 | 최근 작가 피드백과 검수 | 고칠 항목과 보존할 항목이 분리된다 | 보류를 영구 삭제로, 미정을 확정으로 바꾸지 않는다 |

## `story/outline/story_frame.md` — 작품 골격

1.8의 실제 절 이름은 아래 기술 이름이다. 한국어 설명을 붙일 수 있으나 파서·프롬프트가 요구하는 이름과 SECTION 태그는 그대로 둔다. 2.0에서는 같은 의미를 읽기 쉬운 골격에 담되 활성 Skill과 도구 계약을 따른다.

| 항목 | 목적 | 맥락 | 판단 기준 | 적용 경계 |
| --- | --- | --- | --- | --- |
| `01_Theme_and_Tonal_Ground` / 주제 | 무엇을 선택하고 잃는 이야기인지 정한다 | 주인공의 핵심 욕망·결핍 | 주요 승리·실패가 주제의 질문을 변주한다 | `약자가 강해진다` 같은 결과만으로 대체하지 않는다 |
| 같은 절 / 정서·톤 | 독자가 체감할 온도와 강도를 정한다 | 장르와 인물의 생활감 | 유머·긴장·비극의 전환이 사건에 맞는다 | 매 장면을 같은 감정으로 만들지 않는다 |
| 같은 절 / 주인공 참조 | 주인공 원본을 지정한다 | 해당 인물 카드 | 이름과 카드 링크가 일치한다 | 전체 인물 아크를 골격에 재복제하지 않는다 |
| `02_Core_Conflict_and_Foreground_Background_Story_Layers` / 중심 갈등 | 장편을 지탱할 충돌을 만든다 | 양립하기 어려운 욕망·제도·이해관계 | 상대가 주인공 없이도 행동할 이유가 있다 | 적을 단순한 무능·광기로만 설명하지 않는다 |
| 같은 절 / 전경 이야기 | 매 회 독자가 따라갈 표면 목표를 준다 | 의뢰·대결·수련·문파 운영·관계 | 단기 목표의 진전·실패·종결이 식별된다 | 배경 떡밥만 내고 현재 사건을 해결하지 않는 전개를 피한다 |
| 같은 절 / 배경 이야기 | 권을 넘는 원인과 비밀을 연결한다 | 출신·음모·제도적 문제 등 | 전경 사건에 남기는 영향과 회수 영역이 보인다 | 모든 우연을 단일 흑막 탓으로 자동 통합하지 않는다 |
| 같은 절 / 두 층의 인과 | 개별 사건이 장편의 축을 전진시키게 한다 | 단기 문제와 장기 원인의 연결 | 전경의 결과가 배경 이해·세력관계 중 하나를 바꾼다 | 모든 사건을 억지로 핵심 비밀과 연결할 필요는 없다 |
| `03_World_Tonal_Ground` / 세계의 불변 규칙 | 편의적 해결을 제한한다 | 무공·내공·부상·제도·자원 | 승패와 해결이 이미 제시한 규칙으로 설명된다 | 예외는 조건·대가·선행 근거를 갖추며 몰래 규칙을 바꾸지 않는다 |
| 같은 절 / 감각·생활 | 설명을 실제 장면으로 옮긴다 | 음식·돈·길·날씨·소리·생활 동선 | 인물 행동에 영향을 주는 디테일이 쓰인다 | 백과사전식 역사·문파 나열로 본문을 채우지 않는다 |
| 같은 절 / 작품 고유 규칙 | 이 작품만의 선택 조건을 만든다 | 특전·회귀·소속·의무 등 | 사용 조건·한계·대가·알려진 범위가 분명하다 | 회귀·상태창·빙의를 기본 장르 요소로 자동 추가하지 않는다 |
| `04_Endgame_Direction_and_Book_Objective` / 결말 방향 | 계획이 수렴할 목표를 준다 | 주요 약속·주제·인물의 대가 | 마지막에 어떤 상태·관계·사실이 남는지 보인다 | 미정 결말을 이미 발생한 정사로 취급하지 않는다 |
| 같은 절 / 최종 장면 | 추상 목표를 체감 가능한 도착으로 바꾼다 | 장소·행동·인물·감정 | 승리 이후의 변화와 비용을 보여줄 수 있다 | 초안의 장면 연출을 변경 불가 사건으로 고정하지 않는다 |
| 같은 절 / `Book Objective` | 전체 목표의 달성 여부를 확인한다 | 작품 완결 시점 | 외부 관찰자가 달성·미달을 구별할 수 있다 | `최강이 된다`만 적지 않고 지위·문제 해결·관계 상태를 구체화한다 |

## `story/book_rules.md`와 구조화 규칙

기계용 이름·enum을 유지한다. 한국어 서술에는 목적·맥락·기준·경계를 담되 structured 배열·불리언에 설명용 객체를 삽입하지 않는다.

| 실제 항목 | 목적 | 맥락 | 판단 기준 | 적용 경계 |

## 현재 상태·요약·문체·장부

이 영역은 작성자의 희망보다 저장된 실제 본문을 근거로 작성한다. 엔진이 관리하는 manifest·스냅샷·색인은 직접 꾸미거나 예시를 실제 결과로 제출하지 않는다.

| 파일 / 항목 | 목적 | 맥락 | 판단 기준 | 적용 경계 |
| --- | --- | --- | --- | --- |
| `current_state` / `subject` | 사실의 대상을 식별한다 | 인물·조직·물건·장소 | 서로 다른 대상이 혼동되지 않는다 | 주체를 추측으로 합치지 않는다 |
| `predicate` | 어떤 속성·관계인지 나타낸다 | 위치·소속·소유·상태 등 | 같은 속성의 이전 값과 비교 가능하다 | 평가·감상을 사실 속성으로 둔갑시키지 않는다 |
| `object` | 현재 값을 남긴다 | 해당 주체·속성 | 본문에서 확인한 값이다 | 인물의 추정은 사실로 확정하지 않는다 |
| `validFromChapter` | 적용 시작을 남긴다 | 사건의 발생 시점 | 근거 회차와 양립한다 | 설정 변경을 과거 전 회차에 소급 적용하지 않는다 |
| `validUntilChapter` | 사실 만료를 남긴다 | 이사·소속 변경·회복 등 | 새 사실과 유효 기간이 연결된다 | null을 무조건 영원불변으로 해석하지 않는다 |
| `sourceChapter` | 근거를 가리킨다 | 원고 또는 초기 조건 | 근거를 다시 확인할 수 있다 | 계획표를 실제 사건의 출처로 쓰지 않는다 |
| `currentStatePatch.currentLocation` (1.8) | 현재 동선을 고정한다 | 최신 회차 종료 | 다음 장면의 이동 출발과 맞는다 | 장면 전환만으로 순간이동하지 않는다 |
| `protagonistState` (1.8) | 현재 몸·마음 상태를 잇는다 | 부상·피로·감정의 잔여 | 회복·변화에 원인이 있다 | 다음 회차 편의로 대가를 지우지 않는다 |
| `currentGoal` (1.8) | 인물의 당면 목표를 잇는다 | 지금 아는 정보·우선순위 | 다음 행동을 설명할 수 있다 | 작가의 최종 목표와 인물의 현재 목표를 합치지 않는다 |
| `currentConstraint` (1.8) | 당장 못 하는 일을 남긴다 | 시간·돈·신분·부상·약속 | 선택지가 실제로 제한된다 | 새로운 힘을 얻었다고 무관한 제약까지 없애지 않는다 |
| `currentAlliances` (1.8) | 협력의 현재 조건을 남긴다 | 상호 이해·부채·신뢰 | 협력이 가능한 이유·범위가 보인다 | 일회 협력을 영구 충성으로 바꾸지 않는다 |
| `currentConflict` (1.8) | 다음 회에 남은 압박을 잇는다 | 해결되지 않은 실제 문제 | 종료된 문제와 미해결 문제가 분리된다 | 새 문제를 만들어 종료 상태를 허위로 바꾸지 않는다 |
| 요약 / `chapter`·`title` | 사건의 위치를 찾게 한다 | 실제 회차 | 저장 파일·색인과 맞는다 | 예정 회차를 완성 회차로 세지 않는다 |
| `characters` | 실제 관여 인물을 요약한다 | 해당 회차 | 등장·행동·영향의 구분이 가능하다 | 이름 언급만 된 인물을 실제 현장에 배치하지 않는다 |
| `events` | 주요 인과를 보존한다 | 실제 사건 순서 | 원인→선택→결과가 남는다 | 장면을 과장해 새로운 사실을 만들지 않는다 |
| `stateChanges` | 다음 회에 이어질 변화를 남긴다 | 회차 전후 비교 | 위치·능력·관계·자원의 변화가 구체적이다 | 아무 변화도 없는데 성장했다고 쓰지 않는다 |
| `hookActivity` | 복선의 진전·회수를 연결한다 | ID·본문 근거 | 복선 원장과 일치한다 | 예고 문장을 해결 증거로 쓰지 않는다 |
| `mood` | 다음 집필의 정서 맥락을 준다 | 회차 전체와 끝의 여운 | 사건이 만든 감정과 맞는다 | 분위기를 사실·인물 감정 전부의 확정값으로 쓰지 않는다 |
| `chapterType` | 회차 기능을 설명한다 | 실제 장면 구성 | 해결·수련·관계 등 주요 기능이 맞는다 | 유형에 맞추려고 완료 원고의 사건을 바꾸지 않는다 |
| `style_guide` / 문장·대사·호칭 | 작품 목소리를 유지한다 | 시점·관계·장르·독자 | 일관된 높임말과 가독성을 확인한다 | 참고 작품의 고유 문장·대사·장면을 복제하지 않는다 |
| `style_guide` / 묘사·정보량·금지 표현 | 장면의 밀도와 리듬을 조정한다 | 액션·생활·감정 장면의 차이 | 독자가 행동과 감정을 따라갈 수 있다 | 모든 문단 길이와 어휘를 획일화하지 않는다 |
| `particle_ledger` / 자원 (1.8 조건부) | 수급·소모를 연결한다 | 수치 체계를 쓰는 작품 | 증감과 사용 조건이 본문과 맞는다 | 무협 내공을 합의 없이 게임 MP처럼 환산하지 않는다 |
| `subplots`·`emotional_arcs`·`character_matrix` (1.8) | 보조 갈등·감정·인물 상태를 잇는다 | 해당 원본 계약의 자유 구조 | 원고에 생긴 변화와 근거가 있다 | 이 문서가 임의의 공통 JSON 스키마를 새로 정의하지 않는다 |
| 2.0 `factOps.upsert`·`expire` | 사실을 추가·만료한다 | 실제 상태 전이 | 동일 사실의 유효 기간이 맞는다 | 1.8 `currentStatePatch`를 2.0 strict delta로 전송하지 않는다 |
| `hookOps` / `upsert`·`mention`·`resolve`·`defer` | 복선 처리 종류를 구별한다 | 해당 회차의 실제 진전 | 단순 언급과 회수가 구분된다 | 검수 통과를 위해 원장 상태만 바꾸지 않는다 |

## `book.json` — 작품 운용 설정

| 실제 항목 | 목적 | 맥락 | 판단 기준 | 적용 경계 |
| --- | --- | --- | --- | --- |
| `id` | 저장·호출 대상을 식별한다 | 고유 작품 폴더 | 경로 안전성과 참조 일치 | 제목 변경만으로 기존 작품 ID를 자동 변경하지 않는다 |
| `title` | 작품을 독자와 운영자가 알아본다 | 장르·핵심 약속 | 실제 내용과 식별 가능한 연결 | 제목의 과장을 세계관 사실로 취급하지 않는다 |
| `platform` | 형식·독자 관습을 참고한다 | 선택한 유통 환경 | 분량·소개 방식의 참고점이 있다 | 플랫폼 관습을 보장된 흥행 법칙으로 말하지 않는다. 1.8 지원 밖은 `other` |
| `genre` | 장르 지침을 선택한다 | 작가가 고른 독자 약속 | 해당 엔진에서 사용 가능한 지침과 맞는다 | 2.0에 존재하지 않는 1.8 `genres/` 파일이 있다고 가정하지 않는다 |
| `status` | 운영상 진행 상태를 남긴다 | incubating/outlining/active/paused/completed/dropped | 실제 작업 단계와 맞는다 | 소설 속 주인공 상태와 혼동하지 않는다 |
| `targetChapters` | 장편 범위를 계획한다 | 최종 목표와 아크 수 | 해당 분량에 갈등·회수가 들어간다 | 목표 달성 숫자만으로 미완 원고를 완결 처리하지 않는다 |
| `chapterWordCount` | 목표 분량을 정한다 | ko는 공백 제외 글자 수 | 실제 `ko_chars` 계측으로 확인한다 | 필드 이름 때문에 영어 단어 수로 계산하지 않는다 |
| `minChapterLength` (2.0) | 허용 최소 분량을 정한다 | 해당 집필 작업의 요구 | 최소·목표·최대가 서로 양립한다 | 1.8 스키마에 없는 옵션을 지원한다고 안내하지 않는다 |
| `maxChapterLength` (2.0) | 허용 최대 분량을 정한다 | 같은 조건 | 실측과 비교 가능하다 | 상한 준수 때문에 필요한 인과를 잘라내지 않는다 |
| `language` | 집필 언어를 선택한다 | 작품 설정이 프로젝트보다 우선 | 제목·본문·설명이 선택 언어로 나온다 | `ko`가 한국 배경·한국인 이름·현대 시대를 강제하지 않는다 |
| `parentBookId` | 파생 작품의 원본을 지정한다 | 속편·동인·세계 공유 | 참조 대상과 이어받는 사실이 명확하다 | 원본 전체를 무제한 변경·복제하는 허가가 아니다 |
| `fanficMode` | 원작 적용 방식을 고른다 | 실제 파생 요청 | 규칙 카드와 일치한다 | 1.8 enum과 2.0 문자열 차이를 지킨다 |
| `writing.reviewMode` (1.8) | 검토 흐름을 선택한다 | auto/manual | 검토 대기와 자동 진행이 설정에 맞는다 | auto를 사용자 승인·출판 허가로 확대하지 않는다 |
| `writing.revisionGate` (1.8) | 수정본 수용 절차를 정한다 | strict/lenient/always | 해당 정책의 실제 판정을 따른다 | 설정 편의를 위해 거짓 PASS·저장 증거를 만들지 않는다 |
| `createdAt`·`updatedAt` | 저장·변경 시점을 추적한다 | 엔진 운영 기록 | 유효한 실제 시각 | 소설 속 연대와 혼동하거나 과거 성과를 꾸미지 않는다 |

엔진의 연결·API 키·프록시·알림·인증은 소설 설정이 아니므로 이 문서의 작성 대상에서 제외한다. 모델 실행을 추가하지 않으며 Qwen·로컬 추론을 복구하지 않는다. 원본: [1.8 작품 설정](/workspace/inkos/packages/core/src/models/book.ts), [2.0 작품 설정](/workspace/inkos-latest/packages/core/src/models/book.ts).

## 한국 현대 라이트 무협에 적용하는 예

아래는 고정 시장 규격이나 모든 무협의 필수 관습이 아니라, 이번 작업에서 사용하는 편집 기본값이다. 자세한 작품별 선택은 작가 의도가 우선한다. [현대 한국 라이트 무협 기준](현대한국-라이트무협-기준.md)을 함께 사용한다.

| 항목 | 목적 | 맥락 | 판단 기준 | 적용 경계 |
| --- | --- | --- | --- | --- |
| `라이트`의 의미 | 접근성과 읽는 속도를 확보한다 | 현대 한국어 웹소설 독자 | 장면 목표·행동·감정이 이해되고 낯선 어휘가 문맥으로 설명된다 | 유머 의무·전연령·무조건적 승리를 뜻하지 않는다 |
| 협·명분·책임 | 힘을 쓰는 선택의 무게를 준다 | 은원·의리·생계·소속의 충돌 | 구한 사람·감당한 비용·남은 책임이 있다 | 정파=선, 사파=악, 마교=광신으로 자동 확정하지 않는다 |
| 성장·특전 | 다음 단계의 기대를 만든다 | 출발 능력과 투자·위험 | 새 힘이 사용 조건·실패 가능성·대가를 갖는다 | 회귀·빙의·천재·상태창을 자동 도입하지 않는다 |
| 경지·상성 | 독자가 승패를 납득하게 한다 | 내공·숙련·거리·부상·지형 | 기존 규칙·관찰된 기술로 결과를 설명할 수 있다 | 강호 공통 경지표가 있다고 가정하거나 경지 하나로 모든 승패를 정하지 않는다 |
| 문파·세가·방회 | 강호의 이해관계를 만든다 | 재원·인력·위신·관할·동맹 | 조직이 이익과 유지 비용 때문에 행동한다 | 이름만 다른 악역 집단을 대량 나열하지 않는다 |
| 대결 | 기술과 선택의 차이를 보여준다 | 목표·지형·거리·후속 위험 | 동작→대응→손상·소모→결과가 따라간다 | 무공명·경악·압도 묘사만으로 싸움을 대체하지 않는다 |
| 생활·유머·대사 | 동료애·개성·호흡을 만든다 | 나이·서열·친밀도·상황 | 호칭과 높임말이 관계를 반영한다 | 현대 유행어·밈이 배경과 화자 목소리를 무너뜨리지 않는다 |
| 보상·연재 리듬 | 선택의 성과를 체감하게 한다 | 독자가 기다린 약속 | 해결·실력 활용·관계 변화·생활 개선이 실제로 남는다 | 매 회차 복수·신분 공개·절벽 끝맺음을 강제하지 않는다 |
| 적대자·사건 | 갈등이 자체 원인으로 지속되게 한다 | 적의 목표·정보·자원 | 패배 뒤에도 새 조건에 맞춰 행동한다 | 주인공을 돋보이게 하려고 전원이 무능해지지 않는다 |
| 부상·죽음·비극 | 대가의 신뢰도를 유지한다 | 합의한 표현 수위 | 회복 조건·유족·조직·심리의 후과가 남는다 | 라이트 톤을 이유로 손실을 다음 회차에서 지우지 않는다 |

설정 작업이 끝났는지 확인할 때는 각 핵심 항목에서 네 질문의 답을 짚을 수 있는지, 미정과 확정이 구별되는지, 골격→권 지도→인물→규칙→본문→상태가 같은 인과를 유지하는지를 확인한다. 목적에 기여하지 않는 항목을 채우기 위해 세계관을 부풀리지 않는다.
