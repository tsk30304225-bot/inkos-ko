# InkOS 한국어판 운영 규칙 (v1.1, 2026-10-25)

## 역할

| 역할 | 담당 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 결정 | 사용자(참새) | 미정 항목 결정, 인증 정보 등록, 병합 승인 | — |
| 지휘·감독 | Claude (claude.ai 채팅) | 단계 지시, 보고 검토와 승인·반려, 계획서·규칙 갱신 지시, 결정과 교훈 정리(컨텍스트 관리) | 포크 코드를 직접 고치지 않음 |
| 개발 | Claude Code (클라우드 세션) | 포크 코드 작업, 빌드·테스트, 단계 보고, PLAN.md 진행 기록 갱신 | 미정 항목을 스스로 정하지 않음, 승인 전 다음 단계 시작 안 함 |
| 실행 시험 | Grok봇, Codex (클라우드) | 감독이 지시한 실행 시험(브리지로 실제 생성)과 원본 출력 보고 | 포크 코드 수정 안 함 |

## 기준 문서

저장소 안의 문서가 기준이다. 대화 내용, 봇의 메모리, Slack 메시지는 기준이 아니며,
그 안의 결정은 아래 문서에 옮겨 적혀야 효력이 있다.

1. `korean-port/PLAN.md` — 목표, 단계, **결정 사항**, 진행 기록, 시험에서 알게 된 것
2. `korean-port/OPERATING_RULES.md` — 이 문서
3. `CLAUDE.md` — 개발 세션 규칙
4. `tools/inkos-agent-bridge/AGENTS.md` — 브리지 운용 규칙(실행 시험용)

충돌하면 PLAN.md의 결정 사항 → 이 문서 → 나머지 순으로 따른다.

## 작업 흐름

1. 감독이 `[지시]`를 낸다(단계, 범위, 끝 조건).
2. 개발은 작업 브랜치에서만 커밋한다. `master`에 직접 커밋하지 않는다. Claude Code 클라우드 세션은 지정된
   브랜치(`claude/...`)에만 푸시할 수 있으므로 그 브랜치 하나를 쓰고, 커밋 제목에 단계를 적는다
   (예: `feat(ko): ... (stage 5)`). 감독은 단계별 커밋 범위로 검토한다.
3. 단계가 끝나면 `[보고]`를 낸다(아래 양식). 같은 커밋에서 PLAN.md 진행 기록을 갱신한다.
4. 감독이 검토해 `[승인]` 또는 `[반려: 사유]`를 낸다. **승인 전에는 다음 단계를 시작하지 않는다.**
5. `master` 병합은 사용자 승인 후에만 한다.
6. 사용자 결정이 필요하면 누구든 `[결정필요]`를 낸다. 결정되면 감독이 PLAN.md 결정 사항 갱신을 지시한다.

## 보고 양식 (`[보고]`)

```
[보고] <단계> / 브랜치 <이름> / 커밋 <해시>
한 일: (3~6줄)
증거: 테스트 통과·실패 수(기준선 대비), 핵심 명령 출력 원문 일부, 생성 파일 경로
바뀐 파일: (목록)
깨질 수 있는 것: (영어·중국어 동작, 기존 테스트, 실행 환경 영향)
확인하지 못한 것: (못 돌린 시험, 추정으로 남은 부분)
결정필요: (없으면 "없음")
```

요약만 하지 말고 증거 칸에 원본 출력을 붙인다. 감독은 증거 없는 "완료"를 승인하지 않는다.

## 멈추고 보고할 조건

- 원본 테스트 실패 수가 기준선보다 늘었다.
- 계획서에 적힌 사실(파일 위치, 동작)이 실제 코드와 다르다.
- 계획 범위를 넘는 변경(구조 개편, 원본 파일 대량 수정)이 필요해 보인다.
- 미정 항목을 정하지 않고는 진행할 수 없다.

## Slack 보고 머리말

개발 세션의 보고는 `[코드]`, 실행 시험은 `[그록]`·`[코덱스]` 머리말을 붙인다(누가 쓴 보고인지 구분).

## 금지

- API 키·외부 모델 주소 사용. 실제 생성 시험은 브리지로만 한다.
- 인증 정보(드라이브 등)를 저장소·로그·보고에 남기는 것.
- 원본 `.gitignore` 수정(필요한 파일은 `git add -f`로 추적).
- 테스트가 실패한 상태의 커밋을 완료로 보고하는 것.
- 해결되지 않은 문제의 등급을 낮춰 보고하는 것(검수 결과 포함).

## Slack `#inkosgo` 사용

- 태그: `[지시]` `[보고]` `[승인]` `[반려]` `[결정필요]` `[메모]`
- 개발·실행 시험 세션이 Slack에 직접 쓰지 못하면, 사용자가 보고를 채널이나 감독 채팅에 붙여 넣는다.
- 채널 메시지는 기록용이다. 효력 있는 결정은 PLAN.md에 반영된 것만이다.

## 컨텍스트 관리

- 결정은 PLAN.md "결정 사항"에, 시험·실행에서 배운 것은 "알게 된 것"에 적는다.
- 개발 세션은 끝날 때마다 PLAN.md 진행 기록을 갱신하고 푸시한다. 클라우드 세션은 오래 쉬면 사라지므로
  커밋하지 않은 내용은 남지 않는다고 가정한다.
- 감독은 단계마다 "현재 상태 요약"(완료 단계, 열린 결정, 다음 지시)을 채널에 남긴다.
